# 三路线对比记分卡（2026-08-27）

> 评审对象（三实物，同验收剧本）：
> **A** = v2 架构 + WeKnora 原生前端（:5173，经 /sso/native 进入）
> **B** = B1 全栈代理（WeKnora-portal-proxy :8081，单租户+本地权限表）
> **C** = v2 芯 + B1 皮（WeKnora-portal-sim :8082，门户三页+真实 JWT+零过滤）
>
> 打分依据：本会话实测（curl 全链路、越权/回收/过期用例、聊天引用验证）+ 架构分析（标注【推断】）。
> 分值 1-5；权重合计 100。**权重是提案，决策方可按公司优先级调整**（敏感性见文末）。

## 四、结论与建议

1. **推荐 A（v2 + 原生前端）为生产主线**：权限、一致性、生产化差距全面领先；它的两个短板（首屏带宽、新用户 bootstrap）都有明确低成本修复路径。
2. **C 是强力备选**：若"门户必须是自建 UI"是硬性政治/体验要求，C 就是答案——架构与 A 共享，UI 生产化是唯一增量。**A/C 可组合推进：先按 A 上线，C 的门户页作为二期皮肤按需切换**（两者后端完全相同）。
3. **B 的历史使命已完成**：POC 证明了"智能在代理"路线可行且安全测试全过，但其生产化代价（020 重决策+纵深单点）不值得。建议归档不删。
4. **无论 A/C，三个必办项**：新用户 bootstrap（首登自动配默认模型+自动入全员组）、公网带宽提升或静态资源压缩、生产关闭密码登录。

## 五、敏感性说明（哪些权重调整会翻盘）

- 若"自建门户 UI"为一票否决项（权重 D2 中"原生形态"计 0）→ **C 反超 A**（4.0 vs 3.9 量级【推断】）；
- 若公司明确不再跟随 WeKnora upstream（独立产品化）→ B 的 D6 优势消失但 D3/D4 劣势仍在，仍垫底；
- 若安全审计要求"平台侧不可见终端用户身份即不合规"→ B 的 D1/D9 进一步失分，差距拉大。

> 本卡为决策辅助，最终裁决建议结合浏览器人眼验收（三实物 UI 对比）与管理层对"门户 UI 归属"的拍板。
