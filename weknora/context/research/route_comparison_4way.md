## 三、D 方案（Java）已确认的细节与谈判记录

### Java 侧自述方案（2026-08-27，我方推测+对方确认）
1. WeKnora 侧某账号（须为目标租户 **Owner**）在 API 集成面板创建 tenant key 发给 Java；
2. **Java 生成 HMAC 密钥**交 WeKnora 粘贴到签名 Token 模式（密钥两端各持，轮换用 `"***"` 占位语义）；
3. **只用一个 Tenant**（全公司所有 KB 在内）；
4. Java 对接公司 SSO 取**工号**，签 JWT（sub=工号，tenant_id=该租户，aud=weknora，exp≤24h）；
5. Java 自建**工号↔知识库权限映射表**与系统角色（管理员/编辑/浏览），逐请求过滤；
6. Java 管理知识库的创建/编辑/浏览权限与生命周期。

### key 授权方式的交涉（关键谈判点）
- **Java 要求**：授权方式=「空间完全访问」（full_access），知识库范围=全部知识库；
- 动因推断：Java 要经 API 建库/管库，而建库需要 `manage_kbs` 能力或 full access，对方图省事要满权限；
- **我方反建议（发 key 前提出）**：不给 full access，改为**能力清单 `retrieve+ingest+chat+manage_kbs`**——功能完全覆盖其需求（建库/管库/传文档/聊天/检索），但不放行其余管理面路由（成员/模型/密钥管理）。这是决策 020"tenant key 最小权限"条款的直接应用；
- **若 Java 坚持 full access，三项不可谈判配套**：① 8080 安全组白名单只放 Java 服务器 IP；② Java 侧实名审计先于上线；③ key 轮换预案（一键吊销+last_used_at 监控现成）。

### D 方案技术语义备忘（对齐认知用）
- 权限三层真相：key=机器全权；签名 Token=会话按工号分桶标签（`api_external_user:{tid}:{工号}`）；
  **WeKnora 不做用户级判定**——创建/编辑/浏览权限全部=Java 决定"替不替该用户转发该类请求"；
- 红利（B1 实测）：新用户零开通（无需建号/配模型）、会话按人隔离实测通过、接入面单一；
- 账单：纵深单点（Java 过滤 bug=越权）、WeKnora 无实名审计、决策 020 口径需正式修改、
  creator 归因为机器身份、单租户 10GB 配额需调大、模型一次性配一套即可（比 v2 逐空间简单）；
- 已知字段坑（B1 踩过，直接给 Java）：knowledge-chat 请求字段是 `query` 非 `query_text`；
  平台 key 的 X-Tenant-ID 头必须指向真实存在租户否则报误导性 401（D 用 tenant key 不受此影响）；
- 联调工具：`POST /tenants/:id/api-principal-test-token`（Owner 门禁，代签 ≤3600s 测试 JWT）；
- 参考实现：**WeKnora-portal-proxy 即 D 的完整 Go 版样例**（含越权测试用例 404 语义/上传分权/聊天 kb_ids 裁决，可直接当 Java 的验收标准）。

## 四、共存与演进路径（重要结论）

API 通道（D）与 Web 通道（A）**可在同一 WeKnora 实例并存**：
**现在上 D（尊重组织现实，B1 作参考实现）→ v2 资产保留不拆（grants/聚合/分组前端闲置待命）→
触发条件出现时（需要空间概念/Java 门户维护吃力/要求实名审计）经 bridge（工号换票，幂等已验证）
平滑迁到 A。** 代价：v2 资产压箱底 + D 三座大山需写入决策记录。
