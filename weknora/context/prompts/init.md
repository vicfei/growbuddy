## 提示词正文

你好，我将基于 WeKnora 进行二次开发。以下是我的完整设计文档和项目上下文，请先阅读并理解：

### 项目背景
- **项目名称**：WeKnora 资管知识库门户系统（二次开发）
- **业务场景**：为资管企业构建内部知识库门户，管理研报、行业数据、合规文档等核心知识资产。
- **核心需求**：
  1. 四层权限管理（科技管理员/部门管理员/可编辑成员/只读成员）
  2. 层级标签系统（树状结构 + 自动提取 + 手动补充）
  3. 标签预过滤检索（问答前先通过标签筛选范围）
  4. 智能体增强出口（结构化输出、合规审计、强制溯源）
  5. UUM 身份桥接

### 技术栈
| 层级 | 技术 |
|------|------|
| 基础平台 | WeKnora（开源知识管理+RAG 平台） |
| 后端语言 | Go 1.26+（二开主战场） |
| 文档解析 | Python（docreader 微服务） |
| 前端 | Vue 3 + TypeScript |
| 数据库 | PostgreSQL 17（ParadeDB，含 pgvector） |
| 缓存/队列 | Redis 7.0 + Asynq |
| 部署方式 | Docker Compose（开发模式：宿主机运行代码，依赖容器化） |

### 设计文档（请依次阅读）
1. **功能文档**：`.context/design/功能文档.md` —— 宏观架构、实施路线图、权限设计、Agent 增强方案

### 编码规范要求
- **分层架构**：严格遵循 Handler → Service → Repository → Model 分层
- **依赖注入**：使用项目现有的 `di` 容器
- **错误处理**：统一使用 `errors` 包定义的标准错误码
- **日志**：使用项目现有的 `logger` 库
- **数据库**：GORM 查询必须显式处理软删除（`deleted_at IS NULL`）
