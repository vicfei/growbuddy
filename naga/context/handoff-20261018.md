## 工作流规范(血泪教训浓缩)

- **变更闭环**:英文 issue → 分支 → 实现+测试 → PR(Closes #N 后留空格)→
  **显式红绿门禁**(脚本 `.context/merge_gate.sh`,全 pass 才 exit 0;
  **绝不靠 shell && 链**——两次红合并的教训)→ merge commit → pull --ff-only → 双端删分支
- **三门本地先行**:pytest + ruff + pyright strict(push 前)
- 测试纪律:fake 注入零外网;home 一律 tmp_path;SLO 类测试 CI 跳过
  (验收场地=专用主机;`_skip_on_ci` 标记,理由+登记册指针)
- PR 检查不随 main 自动重跑:把 main 合进 PR 分支触发新检查
- GitHub PAT 在 ~/.git-credentials;每次 API 正文 grep `zcode|generated with|🤖`
- pyright strict 常坑:json.loads→cast 收窄;dataclass field(default_factory=list[T])
- 登记册每批次 append;str.replace 无 assert = 静默不命中(必须 assert)
- 好用的观测:`~/.naga/state/daemon.log`(NAGA_WECHAT_DEBUG=1 开原始报文)
