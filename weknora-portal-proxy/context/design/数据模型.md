# 数据模型（portal_proxy 独立库）

> 原则：独立数据库 `portal_proxy`（与 WeKnora 库物理隔离，POC 清场=DROP DATABASE）；
> 不建外键（表内自洽 + 跨库本就无法建 FK，沿用 WeKnora "No FK by design" 惯例）；
> KB 相关实体（知识库/文档/会话/消息）**不落地本库**——它们的事实源是 WeKnora，本库只存"谁对哪个 KB 有什么权限"。

## 表清单

### 1. employees（SSO 模拟的员工目录）

| 列 | 类型 | 说明 |
|---|---|---|
| id | BIGSERIAL PK | |
| uum_user_id | VARCHAR(128) NOT NULL UNIQUE | 工号——全系统对外的用户主键（与 WeKnora external JWT 的 sub 一致） |
| display_name | VARCHAR(128) NOT NULL | 展示名 |
| password_hash | VARCHAR(128) NOT NULL | bcrypt（SSO 模拟页校验用） |
| is_admin | BOOLEAN NOT NULL DEFAULT false | 管理后台门禁 |
| is_active | BOOLEAN NOT NULL DEFAULT true | false=离职禁用（登录与既有会话双双拒绝） |
| created_at / updated_at | TIMESTAMPTZ | |

种子数据建议：`REVIEW-A0001`（管理员）、`REVIEW-U0001/U0002`（普通员工，用于越权对照）。

### 2. kb_permissions（★核心权限表）

| 列 | 类型 | 说明 |
|---|---|---|
| id | BIGSERIAL PK | |
| uum_user_id | VARCHAR(128) NOT NULL | →employees.uum_user_id（逻辑关联） |
| kb_id | VARCHAR(36) NOT NULL | →WeKnora knowledge_bases.id（逻辑关联，跨库） |
| permission | VARCHAR(16) NOT NULL DEFAULT 'viewer' | viewer / editor（本路线只有两档读写语义） |
| category | VARCHAR(32) NOT NULL DEFAULT '团队' | 分组展示标签：个人/团队/公共（模拟空间分组观感，纯展示字段） |
| status | VARCHAR(16) NOT NULL DEFAULT 'active' | active / revoked（过期不写状态，读取时按 valid_until 惰性判定，见下） |
| valid_until | TIMESTAMPTZ NULL | NULL=永久；到期即失效（读取时判断，避免后台清扫器依赖） |
| granted_by | VARCHAR(128) NOT NULL | 授权人工号（审计） |
| reason | VARCHAR(255) | 授权理由（可选） |
| created_at / updated_at | TIMESTAMPTZ | |
| **UNIQUE(uum_user_id, kb_id)** | | 一人一 KB 一行；重复授权=更新 |
| KEY(uum_user_id)、KEY(kb_id) | | 两向查询 |

**有效期语义（POC 简化设计）**：不做后台 ExpirySweeper 定时器；perm 引擎每次读取时判定
`status='active' AND (valid_until IS NULL OR valid_until > now())`。副作用：审计/总览里"过期"
是渲染时推断的状态。若路线胜出转正式，再升级为定时清扫 + status 落库（对应 v2 方案 ExpirySweeper）。

### 3. portal_sessions（门户会话）

| 列 | 类型 | 说明 |
|---|---|---|
| id | VARCHAR(36) PK | 随机 UUID（cookie 值即此 id，哈希后不存明文可选；POC 直存） |
| uum_user_id | VARCHAR(128) NOT NULL | |
| created_at | TIMESTAMPTZ | |
| expires_at | TIMESTAMPTZ NOT NULL | 8 小时滑动过期 |
| KEY(expires_at) | | 清理扫描用 |

登出=删除行+清 cookie。员工 is_active 翻 false 时：登录拒绝 + 既有会话在下个请求被拒（中间件每请求查 employees）。

### 4. audit_log（实名审计——本路线唯一的用户级审计）

| 列 | 类型 | 说明 |
|---|---|---|
| id | BIGSERIAL PK | |
| actor | VARCHAR(128) NOT NULL | 操作人工号；系统动作记 `system` |
| action | VARCHAR(64) NOT NULL | grant / revoke / update_perm / login / logout / denied / upload / search |
| target | VARCHAR(255) NOT NULL | 对象描述（如 `kb:xxx user:REVIEW-U0001`） |
| detail | JSONB NOT NULL DEFAULT '{}' | 变更前后快照、被拒的路径等 |
| created_at | TIMESTAMPTZ NOT NULL | |
| KEY(actor), KEY(action), KEY(created_at) | | |

## 与 WeKnora 数据的关系（只读引用，不复制）

```
portal_proxy.kb_permissions.kb_id ──逻辑引用──> WeKnora.knowledge_bases.id
portal_proxy.employees.uum_user_id ──签发为──> WeKnora 外部 JWT 的 sub
                                              → WeKnora 侧会话归属 api_external_user:{tid}:{sub}
```

KB 的名称/文档数/详情一律实时拉 WeKnora，**本库不做 KB 快照缓存**（避免双写漂移；管理页刷新即拉）。
